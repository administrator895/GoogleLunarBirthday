# Google Lunar Birthday

把 Google 通讯录里的 **“农历生日”** （自定义日期字段），自动变成 Google 日历里的日程。

你只需要在通讯录里记下农历生日，剩下的交给它：每天自动算成公历日期，写成日历事件，往后写几年。

程序只在你的电脑或你自己的 GitHub 仓库里跑，连的是你自己的 Google 账号，中间不经过任何第三方服务器，也不会把联系人存成文件。


## 开始之前：三件准备工作

### 第一件：申请一个「应用专用密码」

程序需要使用你的 Google 账号的「应用专用密码」，这个密码不保存在程序中，只保存在你的本地或者 Github Secrets 里。

1. 打开 [两步验证设置](https://myaccount.google.com/security)，如果还没开就先开——不开就拿不到应用专用密码；
2. 再打开 [应用专用密码页面](https://myaccount.google.com/apppasswords)；
3. 随便起个名字（比如 `农历生日`），点生成，会得到 **16 位字母**；
4. 马上把这 16 位复制下来，页面关掉就再也看不到了。

### 第二件：在日历里新建一个空日历

打开 [Google 日历](https://calendar.google.com)，创建新日历。

名字填 **农历生日**（支持自定义，但是要和 `config.py` 里写的一致，`config.py` 里默认为「农历生日」），其他不用改，点保存。

建议这个日历只放农历生日，别和工作日程混在一起——以后想整体关提醒、整体换颜色都方便。

> 为什么不自动建？因为 Google 只允许人在网页上建日历，程序没这个权限，所以要手工建这一次。

### 第三件：在通讯录里录生日

打开 [Google 通讯录](https://contacts.google.com)，选一个联系人 → 点「修改」→ 找到「日期」这一栏：

1. 点「添加日期」；
2. 类型选 **自定义**；
3. 标签填 **农历生日**（默认匹配此字段，其他字段请稍后在 `config.py` 中添加自定义字段）；
4. 填入农历的年、月、日；

**两个必须注意的地方：**

| 事项 | 说明 |
|---|---|
| 一定要填年份 | Google 允许「只记月日、不记年份」，但程序需要年份才能定位。留空会被判为错误，报 E008。 |
| 不要填 31 号 | 这个日期栏是按公历规则做校验的，所以 31 号能填进去；但农历每月最多 30 天，填了会报 E010。 |

填好之后不用做别的，等程序下次运行，生日就会出现在日历里。


## 跑起来

### 方法一：放到 GitHub 上每天自动跑（推荐）

优点是电脑关机也照跑，不用管。

1. 打开 [新建仓库](https://github.com/new)，填个名字，**务必选 Private（私有）**，其他默认，创建；
2. 把这几个文件传上去：

   ```
   sync_birthdays.py
   config.py
   requirements.txt
   .github/workflows/sync-birthdays.yml
   ```

   层级要保持原样，尤其 `.github/workflows/` 这一层不能少——定时运行靠它。

3. 在仓库里点 `Settings` → 左边 `Secrets and variables` → `Actions` → `New repository secret`，加两条：

   | 名称 | 值 |
   |---|---|
   | `GCONTACTS_EMAIL` | 你的 Gmail 完整地址 |
   | `GCONTACTS_PASSWORD` | 第一件准备工作里那 16 位密码 |

   名称必须一字不差，程序就是按这两个名字去读的。忘了怎么加可以看 [GitHub 官方说明](https://docs.github.com/zh/actions/security-for-github-actions/security-guides/using-secrets-in-github-actions)。

4. 到仓库的 `Actions` 页面，左边选 `sync-birthdays`，右边点 `Run workflow` 手动跑一次，看看有没有报错。

之后每天凌晨 3 点（北京时间）会自动跑。想改时间，编辑 `.github/workflows/sync-birthdays.yml`。

### 方法二：在自己电脑上跑

```bash
pip install -r requirements.txt

export GCONTACTS_EMAIL=你的邮箱@gmail.com
export GCONTACTS_PASSWORD=十六位密码
python sync_birthdays.py
```


## 出错了怎么办

出错不会「悄悄地少一条」，而是让这次运行直接失败，并告诉你是哪里不对。所有报错都长这样：

```
[E008] 张三：标签「农历生日」的日期没有年份（--08-15），请到通讯录里补上出生年份
```

| 错误码 | 什么意思 | 怎么改 |
|---|---|---|
| E001 | 没找到邮箱或密码 | 检查那两个 Secret 的名字有没有拼错 |
| E002 | 登录 Google 失败 | 密码可能失效了，重新生成一个；确认邮箱是完整的 Gmail 地址 |
| E003 | 一个联系人都没读到 | 多半是密码失效。这种情况程序会**直接停下，什么都不写**，避免把日历清空 |
| E004 | 找不到名叫「农历生日」的日历 | 对照 `config.py` 里的名字，看日历是不是建漏了或名字不一致；报错里会列出现有日历 |
| E005 | 某个联系人读不出来 | 那条数据坏了，报错里带编号 |
| E006 | 写了「农历生日」却没填月日 | 去补上月和日 |
| E007 | 日期格式不对 | 比如填成了 `1990/8/5`，用日期选择器重选 |
| E008 | 日期没有年份 | 补上出生年份 |
| E009 | 月份超过 12 | 农历只有十二个月 |
| E010 | 日期超过 30 | 农历没有 31 号 |
| E011 | 农历日期算不出来 | 保底判断，正常数据碰不到 |
| E012 | 写进日历失败 | 多为网络问题，重跑一次；一直失败就看报错里的状态码 |
| E013 | 从日历里删事件失败 | 同上 |
| E014 | 有生日但没有任何名字 | 姓名和昵称都空着，补一个 |

另外有一条保护：**只要有任何一个联系人的数据读不懂，这次就不删任何事件**。「读不懂」和「人已经被删掉」看起来一样，宁可先留着；你改好再跑一次，程序会自己把该删的删掉。


## 你可能会问

**会不会误删我自己在日历里建的日程？**
不会。程序只碰自己写的事件，每条都带一个内部标记（编号以 `@lunar-birthday` 结尾），你手工建的日程它一律不动。

**闰月那年为什么多一条？**
闰月那个月会出现两次（正常月一次、闰月一次），按习俗生日过两次，所以那一年多一条，标题后面带「（闰X月）」。

**提醒在哪里设？**
程序故意不写提醒，因为提醒应该在日历层面统一设：打开 [Google 日历](https://calendar.google.com)，左边「农历生日」日历右侧的三个点 → 设置 → 通知，加一条「全天活动当天 9 点提醒」，所有事件一起生效，以后想改只改一处。

**换账号、或者密码失效了怎么办？**
重新生成一个应用专用密码，去 GitHub 仓库的 Secrets 里把 `GCONTACTS_PASSWORD` 换成新的，代码不用动。

**联系人信息会被存到哪里？**
只在运行时从你的 Google 账号读到内存里，用完就没了。不写本地文件、不进仓库、不发到别处。
